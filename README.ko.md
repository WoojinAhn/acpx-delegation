# acpx delegation

[English](README.md) | [한국어](README.ko.md)

현재 Claude Code나 Codex 대화에서 Grok, Antigravity, Devin에게 작업을 요청할 수
있습니다. 호스트의 네이티브 워커가 외부 요청을 보내고 진행 상황을 관찰해 결과를
반환하는 동안, 부모 에이전트는 다른 작업을 계속할 수 있습니다. 같은 외부 세션에서
후속 요청을 보내거나, 나중에 결과를 회수하거나, 특정 실행을 취소할 수도 있습니다.

[acpx](https://github.com/openclaw/acpx)를 기반으로 동작합니다. 이 패키지는 `rescue`
호스트 연동, 제공자 설정, 실행 식별 기록을 담당합니다. ACP 통신, 프로세스, 큐,
세션, 이벤트 기록은 acpx가 관리합니다.

**초기 릴리스:** 지원 제공자는 **Grok, agy, Devin**입니다. Cursor와 Qoder는 지원
범위에서 제외됩니다. 실제 검증 범위와 제약은 [호환성 검증 기록](docs/compatibility.md)을
참고하세요.

## 설치

Node.js 22.13 이상, npm, 네이티브 서브에이전트와 플러그인을 지원하는 호스트가
필요합니다. 사용할 제공자의 CLI도 설치하고 로그인해 두어야 합니다. 설정 과정에서
제공자 CLI를 설치하거나 로그인을 시작하지 않습니다. 사용할 제공자만 준비하면 됩니다.

**Claude Code**:

```sh
claude plugin marketplace add WoojinAhn/acpx-delegation
claude plugin install rescue@acpx-delegation
```

**Codex**:

```sh
codex plugin marketplace add WoojinAhn/acpx-delegation
codex plugin add rescue@acpx-delegation
```

새 호스트 세션을 시작해 플러그인을 불러오세요. `rescue:setup`으로 버전이 고정된
런타임을 설치한 다음, 사용할 제공자를 확인합니다. Claude Code에서는 다음과 같이
요청할 수 있습니다.

```text
/rescue:setup --install
/rescue:setup grok
```

Codex에서는 `$rescue:setup`을 사용합니다. 실행 도우미는 패키지에 포함된 lockfile을
사용해 **acpx 0.22.0**을 전용 데이터 디렉터리에 설치합니다. 호스트의 플러그인 캐시에는
설치하지 않습니다. 일반 명령은 의존성을 다운로드하지 않습니다. ACP 설정 점검은
프롬프트를 보내지 않고 빈 세션을 생성한 뒤 닫습니다.

설치 명령 문법은 Claude Code 2.1.314와 Codex 0.169.0에서 확인했습니다. 패키지 검증과
실제 실행 도우미 검증은 호스트 UI에서의 명령 탐색과 구분해 기록했습니다. 이 결과만으로
설치된 호스트에서 전체 사용 흐름을 검증했다고 볼 수는 없습니다.

## 대화에서 사용하기

| 작업 | Claude Code | Codex |
| --- | --- | --- |
| Grok Build에 위임 | `/rescue:grok` | `$rescue:grok` |
| Antigravity에 위임 | `/rescue:agy` | `$rescue:agy` |
| Devin에 위임 | `/rescue:devin` | `$rescue:devin` |
| 설정 / 모델 | `/rescue:setup`, `/rescue:models` | `$rescue:setup`, `$rescue:models` |
| 상태 조회 / 결과 회수 / 취소 | `/rescue:status`, `/rescue:result`, `/rescue:cancel` | `$rescue:status`, `$rescue:result`, `$rescue:cancel` |

```text
/rescue:grok --read-only 이 변경에서 놓친 예외 상황이 있는지 검토해줘.
/rescue:agy --model gemini-4-argon --effort high --background 스펙을 검토해줘.
/rescue:devin 현재 체크아웃에서 이슈 #42를 구현해줘.
/rescue:result exec-<id>
/rescue:grok --resume exec-<id> 수정된 취소 경로를 다시 검토해줘.
/rescue:cancel exec-<id>
```

위 예시는 호스트 워크플로에 보내는 요청입니다. 네이티브 워커가 작업마다 실행 도우미를
정확히 한 번 호출합니다. 단일 작업은 기본적으로 결과를 기다립니다. `--background`를
지정하면 워커에 작업을 맡긴 뒤 부모 에이전트가 계속 진행합니다. 여러 모델에 요청하면
호스트가 허용하는 동시 실행 범위에서 각각 새 백그라운드 워커를 사용합니다. 세션이
달라도 작업 디렉터리(cwd)가 같으면 파일은 공유됩니다.

새 작업은 기본적으로 쓰기가 가능합니다. `--read-only`는 제공자의 읽기 전용 제약을
적용하고, 쓰기 권한 요청의 자동 승인을 거부하며, 파일을 변경하지 말라는 지시를
추가합니다. **OS 샌드박스가 아니며**, 셸을 통한 테스트 실행을 보장하지 않습니다.
워크트리 생성은 이 플러그인의 범위에 포함되지 않습니다. 이미 만든 워크트리를 작업
디렉터리로 전달하세요.

## 모델 선택과 후속 요청

- **agy:** 정확한 ACP 모델 ID를 선택하거나 기본 설정으로 명시적으로 저장해야 합니다.
  사용자 선택 없이 기본 모델이나 Auto를 사용하지 않습니다. ACP 모델 목록에서는
  `gemini-4-argon`과 추론 수준 `high`가 분리되어 있습니다. 기존 print 모드의 모델 ID를
  자동으로 변환하지 않습니다.
- **Grok과 Devin:** 명시한 모델이나 저장된 기본 설정을 우선합니다. 둘 다 없으면
  제공자의 기본 모델을 사용하고, 기본 모델을 사용했다는 사실을 표시합니다.
- 명시한 모델과 effort는 제공자가 지원한다고 알려 준 값이어야 하며, 프롬프트를 보내기
  전에 확인합니다. 지원하지 않는 선택이나 결과가 불확실한 요청을 다른 모델로 대체하지
  않습니다.
- 모델 목록은 검색과 페이지 조회를 지원합니다. 조회만으로 기본 설정을 저장하지
  않습니다. 기본 설정은 제공자별로 저장하며 두 호스트가 공유합니다.
- 후속 요청은 모델, effort, 접근 권한을 그대로 이어받습니다. 하나라도 바꾸려면 새
  실행이 필요합니다. 원래 제공자 세션이 없거나 변경되었다면 후속 요청을 거부합니다.

새 실행과 이어가기 중 하나를 명시하지 않으면, 호스트가 해당 제공자와 cwd에서 이어갈 수
있는 가장 최근 실행을 제안합니다. `--fresh`는 별도 작업을 시작합니다. 명확한 후속
요청이라면 다시 묻지 않고 기존 실행을 선택할 수 있습니다.

## 결과, 시간 제한, 취소

실행 접수 결과에 포함된 통합 실행 ID를 보관하세요. 네이티브 워커 ID, acpx 요청 ID,
제공자 세션 ID와는 서로 다릅니다. 완료로 판단하려면 해당 요청과 일치하는 최종 acpx
`turn_result`가 있어야 합니다. 큐가 정상이라는 상태나 일부 응답 텍스트만으로는 부족합니다.

워커는 한 번에 최대 60초씩, 전체 최대 15분 동안 실행을 관찰합니다. 관찰 시간이 끝나도
외부 작업은 계속 실행됩니다. `rescue:result`로 보관 중인 결과를 나중에 회수할 수
있습니다. 이벤트 기록이 사라졌거나 보관 기간이 지났다면 상태를 알 수 없다고 보고합니다.
제출 확인 응답을 받지 못했다고 요청을 다시 보내지는 않습니다.

취소 시에는 세션 잠금을 잡은 상태에서 최신 실행, acpx의 요청 ID, 최종 결과를 확인한 뒤
acpx를 호출합니다. **취소 요청**과 **취소 확인**을 구분합니다. 이 보호는 플러그인을
통한 작업에 적용됩니다. 같은 OS 사용자가 acpx를 직접 동시에 호출하면 이 잠금을 우회할
수 있습니다. ACP 취소는 외부 에이전트가 취소 요청에 협조하는 방식입니다.

Devin에는 호환성을 위한 예외가 있습니다. 검증한 CLI에서는 새로 만든 빈 제공자 세션을
다시 불러올 수 없습니다. 따라서 첫 프롬프트는 acpx의 공개 CLI 큐 경로로 제출하고,
그 결과로 확정된 제공자 세션 ID를 연결합니다. 모든 후속 요청은 원래 세션만 이어가도록
검증하는 공유 런타임을 사용합니다. 숨겨진 초기화 프롬프트, 제공자 출력 파서, 별도의
프로세스 관리자는 사용하지 않습니다. 큐 접수 확인은 `queued`로 기록하며, 프롬프트가
실제로 전송됐다는 확인과는 구분합니다.

## 저장 위치와 업그레이드

실행 식별 기록과 기본 설정은 `$XDG_DATA_HOME/acpx-delegation` 또는
`~/.local/share/acpx-delegation`에 저장됩니다. acpx의 세션과 이벤트 기록은 acpx가
별도로 관리합니다. 두 호스트는 같은 통합 데이터를 사용합니다. 런타임 디렉터리 이름에는
acpx 버전과 패키지에 포함된 lockfile의 해시가 들어갑니다.

개발 시 `RESCUE_DATA_DIR`로 통합 데이터 저장 위치를 분리할 수 있습니다.
`RESCUE_RUNTIME_DIR`는 정확한 버전으로 미리 준비한 런타임 패키지를 지정합니다.
이 설정으로 acpx 자체의 저장소까지 분리되지는 않으므로, 테스트에서는 고유한 세션 이름과
cwd를 사용합니다. 비정상 종료로 남은 설치·세션 잠금은 자동으로 해제하거나 가로채지
않습니다. 기록된 작업을 확인한 뒤 해당 잠금만 수동으로 복구해야 합니다.

호스트 플러그인은 명시적으로 업그레이드하세요. 고정된 런타임이 바뀌었다면 설정을 다시
실행합니다. acpx 버전을 고정해도 제공자 CLI나 클라우드 동작까지 고정되지는 않습니다.
런타임 버전을 변경할 때는 테스트용 ACP 에이전트를 사용하는 테스트와 관련 제공자의 실제
호환성 검증을 수행해야 합니다. 일반 사용 중에 제공자를 자동 업데이트하거나 전역 acpx
설치로 대체하지 않습니다.

## 개발과 설계

```sh
npm ci --ignore-scripts --no-fund
npm test
node plugins/rescue/scripts/rescue.mjs --help
```

테스트는 제어 가능한 테스트용 ACP 에이전트와 실제 고정 버전의 acpx 공유 런타임을
사용합니다. 원래 세션만 이어가는 동작, 요청과 결과의 일치, 관찰 시간 만료, 취소,
제출 결과가 불확실한 상황을 검증합니다. 설치기 테스트는 오프라인 npm 테스트 대역을
사용합니다. 실제 제공자 검증은 명시적으로 실행하며 CI에는 포함되지 않습니다.

개발은 [이슈 기반](https://github.com/WoojinAhn/acpx-delegation/issues)으로 진행합니다.
[스펙](docs/specification.md), [Gemini 검토 및 반영 기록](docs/spec-review.md),
[호환성 검증 기록](docs/compatibility.md)을 참고하세요.
[독립 구현 리뷰](docs/implementation-review.md)에는 발견 사항, 수정 내용, 검증 한계를
기록했습니다.

이 프로젝트는 [rescue-plugins](https://github.com/WoojinAhn/rescue-plugins)의 관련
워크플로를 이어받습니다. Grok과 agy를 유지하고 Devin을 추가하며, 두 호스트에 네이티브
연동을 제공합니다. 기존 플러그인과 과거 기록을 자동으로 삭제하거나 가져오지 않습니다.
기존 명령 이름과 내부 작업 기록 형식의 호환성은 보장 범위에 포함되지 않습니다.
